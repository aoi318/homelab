# HomeLab v1 基本設計

## 1. 基本方針

- Proxmox VEを仮想化基盤として使用する。
- VMは役割ごとに分離し、構成・設定をGitで管理する。
- OSやコンテナは再構築可能とし、バックアップ対象は永続データに限定する。
- 外部公開はゲームサーバーだけに限定する。
- ネットワーク検証用Labは通常環境から完全に分離する。
- 必要最小限の構成から開始し、運用しやすさを優先する。

実際のIPアドレス、VLAN番号、ホスト機種、ユーザー名、鍵の保存先などの環境依存値は、Git管理しない内部設計書で管理する。

## 2. 物理基盤

既存のノートPCを単一のProxmox VEホストとして使用する。

- CPU: 仮想化支援機能を持つモバイル向けCPU
- メモリ: 16GB
- ストレージ: 512GB SSD
- VM用ストレージ: LVM-thin

利用可能なメモリを超えない範囲でVMへ割り当て、ゲームサーバーと検証環境を同時に動かせる余裕を確保する。

## 3. VM構成

| VM | 役割 | vCPU | RAM | Disk | 起動方針 |
| --- | --- | ---: | ---: | ---: | --- |
| OPNsense | ルーティング、Firewall、NAT、DNS、NTP | 2 | 2GB | 16GB | 自動起動 |
| infra01 | Discord Botなどのインフラサービス | 2 | 2GB | 32GB | 自動起動 |
| game01 | Docker上のゲームサーバー | 4 | 6GB | 100GB | 必要時のみ |
| lab01 | OSPFなどのネットワーク検証 | 2 | 2GB | 32GB | 必要時のみ |

通常時はOPNsenseとinfra01だけを起動する。ゲームサーバーはDiscord Botから必要に応じて起動する。

## 4. VM共通設計

- Firmware: UEFI
- Disk controller: SCSI
- Network device: VirtIO
- OS: Debian
- 管理通信: SSH公開鍵認証

通常VMではrootのSSHログインを禁止する。lab01だけはネットワーク検証の操作性を優先し、必要に応じて例外とする。

## 5. ネットワーク設計

通常環境はVLANで次の役割へ分離する。

| ネットワーク | 役割 |
| --- | --- |
| Management | Proxmox、OPNsense、管理端末の管理通信 |
| Infra | Discord Botなどのインフラサービス |
| Game | ゲームサーバー |

Proxmoxの通常用ブリッジはVLAN-awareにする。OPNsenseがVLAN間ルーティング、Firewall、NAT、DNS、NTPを担当する。

Labは別ブリッジへ接続し、通常ネットワークやOPNsenseへのL2/L3経路を持たない完全分離ネットワークとする。Lab内でDNSやNTPが必要になった場合は、Lab内に個別に構築する。

## 6. Firewallと外部公開

- 既定拒否とし、必要な通信だけを許可する。
- 管理端末からのみProxmox、OPNsense、各VMへの管理通信を許可する。
- InfraからGameへの通信は、Discord Botによる制御に必要な範囲だけ許可する。
- GameからInfraおよびManagementへの通信は原則禁止する。
- Labから通常環境への経路は作らない。
- Internetから公開するのはゲームサーバーだけとする。

外部公開は、家庭用ルーターとOPNsenseで必要なゲームポートだけを転送する二段の制御とする。

## 7. サービス設計

### OPNsense

- VLAN間ルーティング
- FirewallとNAT
- 内部DNSとNTP
- ゲームサーバー向けポートフォワード

### infra01

- Discord Bot
- 将来の監視、ログ収集、リバースプロキシなどのインフラサービス

Discord BotはProxmox APIでgame01の起動・停止を行い、専用サービスユーザーへのSSH経由でゲームコンテナを操作する。認証情報はVM上の環境変数ファイルで保持し、Gitへ登録しない。

### game01

Docker Composeでゲームサーバーを運用する。外部公開するのはゲームの必要ポートだけとし、ゲームワールドデータを永続データとして扱う。

### lab01

OSPF、ルーティング、Firewallなどのネットワーク検証を行う。通常環境と分離されるため、検証の失敗が日常利用へ影響しない。

## 8. バックアップと復旧

バックアップ対象は次に限定する。

- ゲームワールドデータ
- Discord Botの設定・データ

ゲームサーバー停止後、Proxmox側から専用の限定権限アカウントへ接続し、ゲームワールドを圧縮して保存する。最新1世代を保持する。

障害時はVM全体を復元するのではなく、Git上の定義からVM・OS・Dockerを再構築し、永続データだけを復元する。

## 9. Secret管理

Gitへ登録しないもの:

- APIトークン
- Discordトークン
- SSH秘密鍵
- 環境変数ファイル
- ゲームワールドデータ

秘密情報はVMまたはProxmoxホスト上の権限を限定した場所に保存する。Git管理する設定には、環境依存値や秘密情報を直接書かない。

## 10. 設計思想

このHomeLabは、次の考え方を基本とする。

- VMは使い捨て可能にする
- 設定をGitで再現可能にする
- 永続データだけをバックアップする
- 外部公開範囲を最小限にする
- Labを完全分離する
- 現時点で不要な機能を実装しない
